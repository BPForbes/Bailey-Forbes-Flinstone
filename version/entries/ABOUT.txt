Version release notes use *.ver files (MAJOR_VERSION, STANDARD_VERSION,
RELEASE_VERSION or MINOR_VERSION / VERSION_PATCH, DESCRIPTION, and optional
RELEASE_DATE).

DESCRIPTION may be:
  - One line:   DESCRIPTION=...
  - Multiline:  DESCRIPTION<<DELIM
                ...any amount of text, multiple lines...
                DELIM
                (closing line is DELIM alone after trim; newlines are kept.)

Optional RELEASE_DATE=YYYY-MM-DD records the release calendar day. If omitted,
scripts/gen_version_changelog.c uses the local calendar date at generation time
(time.h). After a push to develop, version-lock GitHub Actions runs
stamp_version_release_date.sh (after finalize) to append RELEASE_DATE to any *.ver
that does not already have one, in both version/locked and version/entries.

version/entries/  — author and edit .ver release notes here before finalize.
version/locked/   — published snapshot: replaced by copying entries → locked.

Finalize (copy all of entries over locked), then regenerate the shell header:

  ./scripts/finalize_version_locked.sh   # or: make finalize-version-locked
  make                                   # or: ./scripts/gen_version_def.sh

userland/shell/version_def.h is generated from the highest A.B.C among
version/locked/*.ver only. Do not edit the header by hand.

The repository currently ships e.g. 001_2_2_4_baseline.ver. Author new releases as
additional *.ver files under version/entries/ (include the semver in the basename,
often with a serial prefix). Ordering uses MAJOR/STANDARD/RELEASE inside the file,
not the filename prefix.

version/locked/* is a mirror only: it must byte-match version/entries/ for each
locked file. Do not hand-edit locked copies; never let locked diverge from entries.
