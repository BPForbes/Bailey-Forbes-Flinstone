Network segment

Pod (private group)

A pod is a private, named group for one MitM + RS exercise. Membership is keyed on your real logged-in account (the Users and sessions panel below) — open a second session as another account to add a second member. The pod host is a member that is not also hosting the real server session, so one identity never relays both lab and server traffic.

Reverse shell (simulated)

Listen makes you the attacker; another pod member's Accept makes them the victim. Once bound, the attacker's netlab <cmd> in the terminal runs in a fresh, isolated sandbox labeled for the victim — never the victim's real account, files, or terminal. Either side can End it. Accepting isolates the lab from the real network, the same as Start demo below; ending restores it.

The lab auto-joins a shared WebSocket room when it reaches Ready so visitors on this site can talk. Host / Join reconnect; Leave disconnects. If the public hub is down, this browser falls back to a same-origin BroadcastChannel (tabs on one machine only).

Files

            
Send a file from the lab shell to a user on the server. With KeyQuorum co-signed, it is signed by you and sealed to them; the server host checks your signature and releases it only after they co-sign, and only they can open it (server file send -t). Each user publishes their public keys when they connect, and the host keeps the first keys it sees for a name, so give each person their own user.
