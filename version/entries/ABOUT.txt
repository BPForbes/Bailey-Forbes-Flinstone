Version release notes use *.ver files (MAJOR_VERSION, STANDARD_VERSION,
RELEASE_VERSION or MINOR_VERSION / VERSION_PATCH, optional PRERELEASE and
PRERELEASE_ITER, DESCRIPTION, and optional RELEASE_DATE).

DESCRIPTION may be:
  - One line:   DESCRIPTION=...
  - Multiline:  DESCRIPTION<<DELIM
                ...any amount of text, multiple lines...
                DELIM
                (closing line is DELIM alone after trim; newlines are kept.)

RELEASE_DATE (optional in entries):
  Authors usually omit RELEASE_DATE when editing version/entries/*.ver. After
  changes land on the develop branch, the "Version lock on merge" GitHub Actions
  workflow runs finalize_version_locked.sh, then stamp_version_release_date.sh,
  which appends RELEASE_DATE=YYYY-MM-DD to any *.ver under version/locked and
  version/entries that does not already declare RELEASE_DATE, using the merge
  calendar day. For merge date metadata, rely on that automation—do not hand-date
  every new entry unless there is a deliberate reason to freeze an earlier date.

  If RELEASE_DATE is omitted entirely, scripts/gen_version_changelog.c may use
  the generator's local calendar date at generation time (see that script).

PRERELEASE / preproduction directories (not in version_def.h VERSION string):
  PRERELEASE=0 or omit for GA rows kept at the root of version/entries/ (and
  version/locked/) as *.ver. PRERELEASE=1 marks a prerelease: the .ver file must
  live in a subdirectory named exactly:
      preproduction <A>.<B>.<C>/
  where <A>.<B>.<C> matches MAJOR.STANDARD.RELEASE in that file (example:
  version/entries/preproduction 4.0.0/my_release.ver). Filenames stay A_B_C_slug.ver
  (no extra component in the basename). Use PRERELEASE_ITER=<positive int> and bump
  with ./scripts/bump_prerelease_iter.sh between iterations. userland/shell/version_def.h
  still reports only A.B.C (PRERELEASE fields are metadata). Before merging version
  trees into main, run ./scripts/promote_preproduction_for_main.sh: picks the
  highest PRERELEASE_ITER among PRERELEASE=1 files in each preproduction folder,
  writes a GA copy at the tree root with PRERELEASE=0 (keeping PRERELEASE_ITER as the
  final iteration number), removes the preproduction directory. CI runs
  check_version_prerelease_layout.sh on all branches and check_version_main_prerelease_policy.sh
  on main and on PRs targeting main.

version/entries/  — author and edit .ver release notes here before automation publishes.
version/locked/   — published snapshot: full copy of version/entries/ when finalize
                   or Version lock on merge runs on develop.

Finalize (copy all of entries over locked), then regenerate the shell header
(maintainers or local release prep — automation does this after push to develop):

  ./scripts/finalize_version_locked.sh   # or: make finalize-version-locked
  make                                   # or: ./scripts/gen_version_def.sh

userland/shell/version_def.h is generated from the highest A.B.C among all
version/locked/**/*.ver files (recursive). Do not edit the header by hand.

For routine feature work: edit under version/entries/ (root *.ver and optional
preproduction A.B.C/ subtrees) for semver and release prose.
Do not commit hand-edited version/locked/*.ver or userland/shell/version_def.h on
typical agent-authored PRs; GitHub Actions copies entries → locked and regenerates
the header after merge to develop. Exception: this ABOUT.txt file (companion
documentation) may change together with the copy under version/entries/ or
version/locked/ so both stay byte-identical when CI requires it.

The repository ships e.g. 001_2_2_4_baseline.ver. Author new releases as
additional *.ver files under version/entries/ (include the semver in the basename,
often A_B_C_short_slug.ver). Ordering uses MAJOR/STANDARD/RELEASE inside the file,
not the filename prefix.

version/locked/**/*.ver mirrors version/entries/: each locked file must byte-match
the same relative path under version/entries/ for CI. Do not hand-edit locked .ver copies;
never let locked release prose diverge from entries.
